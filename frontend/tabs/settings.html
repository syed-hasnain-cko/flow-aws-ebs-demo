Account Settings

Test your own Checkout.com account: enter your sandbox credentials below and every request from this app uses them instead of the server defaults. Leave a field empty to keep using the default. Secrets are sent once, sealed (AES-256-GCM) on the server and kept in this browser only as an encrypted token — they are never shown again and the server stores nothing.

Good to know

  • Webhooks: in your Checkout.com dashboard point a workflow at with the header Authorization: <your webhook secret> — events for your account then show up in the app. Verification of custom secrets is per server instance, so re-save if a webhook is rejected after a long idle period.
  • Public key (pk_…), processing channel and currency account are not secrets: the browser uses them directly to start Flow and wallets.
  • Base URL / access URL must be Checkout.com hosts (https://[prefix.]api.sandbox.checkout.com); anything else is rejected so your keys can never be sent elsewhere.
  • Not covered: the Forward API, Stripe and Adyen tabs have their own credentials. A saved configuration cannot be revoked before it expires — use a short duration and sandbox keys only.
  • Pay attention to the environment: a sandbox key with a production URL (or the reverse) is rejected by Checkout.com with 401.
